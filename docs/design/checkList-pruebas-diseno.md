# CheckList para la prueba del diseño
Para lograr el objetivo de este checkList se debe de haber cumplido con los siguientes aspectos: 

[ ] Revisión cruzada para verificar que las entidades, claves foráneas y restricciones del esquema relacional coincidan exactamente con las necesidades del negocio agrícola.

[ ] Los diagramas de componentes y despliegue fueron evaluados en equipo para confirmar que modelan la arquitectura global de la aplicación y no se limitan a un caso de uso aislado.

[ ] Se verificó en el diseño técnico que la separación entre controladores, servicios y repositorios evite acoplamientos indebidos.

[ ] Se simularon las tareas críticas para contar el número de pasos y detectar fricciones.

[ ] Los mockups contemplan tamaños de texto grandes, áreas de toque cómodas y contrastes adecuados para ser operados en cualquier dispositivo.

[ ] Se diseñaron y revisaron los estados iniciales de los paneles.

[ ] El diseño contempla las rutas de fallo,por ejemplo, qué visualiza el usuario si intenta comprar un producto cuyo stock cambió o si la conexión a internet falla durante el proceso.

[ ] Se contrastó el diseño de las pantallas y de los componentes de backend para garantizar que un comprador no pueda acceder a las funciones de administración o gestión de cosechas del agricultor

[ ] Los payloads(Cuerpo o Body) y endpoints diseñados aseguran que no se expongan datos sensibles innecesarios entre el cliente y el servidor.
