# Política de Revisión Cruzada

## Descripción

La revisión cruzada establece el procedimiento mediante el cual los cambios realizados en el proyecto son evaluados por otro integrante del equipo antes de ser integrados al repositorio. Esta práctica permite garantizar la calidad del código, validar el cumplimiento de los requisitos y reducir la posibilidad de errores durante el desarrollo.

## Lineamientos

- Todo Pull Request debe ser revisado por al menos un integrante del equipo.
- El autor de los cambios no podrá aprobar su propio Pull Request.
- La revisión debe verificar el cumplimiento de los requisitos definidos para la tarea.
- Se debe validar la calidad del código y el funcionamiento de la solución implementada.
- Las observaciones identificadas durante la revisión deberán ser corregidas antes de la aprobación.
- Solo los Pull Requests aprobados podrán ser fusionados a la rama de desarrollo.
