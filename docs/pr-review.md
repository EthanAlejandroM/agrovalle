# Revisión de la Política de Aprobación de Pull Requests

## Objetivo

Verificar la aplicación del proceso de revisión y aprobación de Pull Requests dentro del repositorio del proyecto, con el fin de garantizar la calidad de los cambios integrados al desarrollo.

---

## Revisión Realizada

Se realizó una revisión de la sección Pull Requests del repositorio en GitHub para analizar el flujo de integración de cambios y la evidencia de revisiones efectuadas antes de la fusión del código.

---

## Hallazgos

- Se identificó el uso constante de Pull Requests para la incorporación de nuevas funcionalidades, correcciones y actividades de documentación.
- Se evidenciaron solicitudes de extracción con estado Approved, indicando la existencia de un proceso de revisión previo a la integración de cambios.
- Los Pull Requests revisados muestran un historial de seguimiento y control sobre las modificaciones realizadas en el proyecto.
- La estrategia utilizada favorece la colaboración entre los integrantes del equipo y contribuye a la detección temprana de posibles errores.

---

## Conclusión

De acuerdo con la revisión realizada, el proyecto implementa un mecanismo de control de cambios basado en Pull Requests, permitiendo validar las contribuciones antes de su integración al repositorio. Esta práctica fortalece el aseguramiento de la calidad del software, mejora la trazabilidad de las modificaciones y promueve el trabajo colaborativo dentro del equipo de desarrollo.
